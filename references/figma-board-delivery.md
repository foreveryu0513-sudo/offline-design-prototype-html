# Figma 交付大画板

适用于本用户跨项目的设计交付总览。具体颜色、尺寸、方案数量与业务内容以当前项目为准。页面特定要求不作为跨项目默认规则。

## 记住这句话

**页面、方案和状态区先分组，再横排；放不下才换行；通用内容独立。前置文案（背景、难点、目标、策略）必须纵向排列，禁止套用横排规则；详见 [前置文案强制要求](../SKILL.md#前置文案必须纵向排列强制)。**

## 写入前先规划占地

1. 先区分前置文案与页面方案区：前者强制纵向排列，后者才适用下列二维占地原则。看用户指定的真实交付模板，不只抄背景色。继承标题栏、层级、字号、页图比例、分组与流程的组织方式。
2. 列出各内容组的真实宽高：方案、方向、页面状态、说明、通用交互。先计算横排占地，再决定画板宽高；可调整外壳宽高适配本次内容，不机械复制模板的空白宽度或按文档逐节向下堆。
3. 同级方案并排比较，同一方案的方向并排放在其标题下。说明紧贴所属组，字号低一级。公共详情、领奖、异常等跨方案复用内容单独标为通用模块，不放进最后一个方案冒充其专属能力。
4. 页面数量多时扩大画布宽度、使用横向分区或同级嵌套列。只有本行真实放不下，或语义确实需要独立区，才换行。层级变化本身不是换行理由。
5. 不把一个孤立长页面的高度变成整张画板下一行的起点：可在其旁边用独立列安排其他完整内容组。顺序由分区标题与空间关系保证，不强迫所有列共用最长列的底边。
6. 若展开态、空态或其他状态只用模块卡片说明，不放完整页面，将卡片放在原页面旁并与原模块的顶部或关键内容基线对齐。状态标题和说明贴近卡片；不要仅对齐整张手机页的顶部。用户已指定独立状态区时遵循该分组，不机械移动回主页面旁。

## Figma 结构

- 页面本体保留原尺寸和内容，不为省空间缩小文字、拉伸手机页、裁掉内容或合并已确认状态。整理交付外壳不等于修改产品本体；用户明确要求修复页面时，仅修改与缺陷直接相关的属性。截断真实正文必须有用户授权；已授权内容修改所导致的空白回收，应同步完成，不保留旧页面高度。
- 内容组使用 Auto Layout；外层可用横向行 + 独立纵列、嵌套网格等二维结构。禁止把所有一级模块放进一个单列纵向 Auto Layout 后依次堆下去。
- 参考模板决定样式，不锁死不适配本次内容的空白。原稿页面与未定稿可编辑性保留；用户要求不建组件时不得组件化。

## 内容变化后的自动伸缩

先判断当前对象是随内容变化的完整页面、滚动内容层，还是有明确尺寸要求的设备视口或弹层预览。前两者应随内容增减伸缩；固定视口保留设备高度，由内部内容和滚动范围变化，不能将所有短页压成小块。

- 删除、折叠、迁移内容后，沿父级检查正文、页面、背景、状态容器和交付分组。保留合理底部留白及安全区，清除旧固定高度、占位节点和旧坐标造成的空白；背景必须覆盖当前内容，不多留旧高度，也不能比内容短。
- 用 Auto Layout / Hug 或等价的内容驱动结构建立依赖。背景跟随承载内容的容器；只把外框手动缩短一次不算解决根因。不能用裁切、遮挡、隐藏真实正文或缩小字体来伪造紧凑。
- 间距分别处理：页面内部沿用当前产品的间距规范；交付外壳按标题、说明、页面与分组关系收紧。后续模块跟随前项真实底边，不继续使用修改前的位置；并列短页不强行补白到最长页。具体间距数值和页面特例留在项目记录。
- 验证一次真实的内容减少与恢复：页面和背景应同步缩短、恢复；后续模块随之移动，已确认内容及宽度不变。优先在副本测试；在原稿临时隐藏时必须恢复并核对最终状态。
- 最后看完整页面底部和完整交付板，确认没有遗留空壳、过大组间空隙、截断或背景脱节，并重新定位受影响的连线及点击说明。不能只检查正文已变短就报告完成。

## 流程箭头

本节的具体样式取自 [巴西接单乐交付画板 1:14165](https://www.figma.com/design/roe8QFl3yBhQklSYGNdhcV?node-id=1-14165)；用户指定其他已确认模板时，先继承该模板的实际连线样式。1:14165 上的常规流程线可直接复制为母版：橙色 `#FF7617`（Figma 源色值约为 R 1、G 0.46409、B 0.08850）、线宽 4 px；起点使用 `CIRCLE_FILLED` 实心圆点，终点使用 `ARROW_EQUILATERAL` 实心等边三角箭头。需要折角时，折点的 `cornerRadius` 为 60 px；直线不额外加圆角。不要用文字箭头、独立圆形和三角形拼出不同的视觉样式。画板中个别长回绕线颜色与常规线不同，不作为默认色。

- 单页设计交付按“主页面结构与设计理由 → 主页面并列状态 → 独立跨页路径”的职责阅读。参考 [巴西接单乐老客流程交付板 206:17246](https://www.figma.com/design/roe8QFl3yBhQklSYGNdhcV?node-id=206-17246) 与 [墨西哥保险首页交付板 206:31400](https://www.figma.com/design/roe8QFl3yBhQklSYGNdhcV?node-id=206-31400)：它们把方案、状态展示和有起终点的操作路径按内容分组；位置可因画布空间调整，语义边界不可混。
- 页面结构区的文字只解释为什么这样组织页面。展开态、空态等并列状态可贴在对应主页面或模块旁边，并对齐原模块锚点；这些卡片是状态对比，不是跳转路径，不用线把它们串成步骤。页内 Expand、弹层这类明确的操作前后关系，可在来源和结果之间就近画局部箭头，但不能跨接到独立查询路径或整个详情状态组。
- 跨页面路径必须单起标题，只放讲清一次真实跳转所需的入口页、中间页和代表性目标页，按实际点击顺序连接；没有中间页时不硬凑。只在首次出现的可点击入口到下一页之间画线；整卡、列表行、图标等无文字入口也要核对。目标页的其他状态另起状态组平铺，不从路径末端连到每张状态页，也不在路径区另外摆一组零散入口卡片。
- 首页、活动页等若只是用户举的上游路径示例，不得抢占本次设计对象；确有必要时在相关交互位置补充来源关系。
- 起点优先贴近真实按钮、图标或点击区域，连线作为交付标注叠在来源页面上方；“页面上方”指图层叠放，不是页面顶部。不要一律把起点移到页外侧边或页面中段。允许从控件旁沿页面空白横向出线，但不得遮住控件文字或重要信息。
- 相邻目标优先水平直连，箭头到目标页面最近的可辨认边缘即可；不强制接到目标标题、某个字段或弹层标题，因此不要为追逐目标标题高度增加折角。若确需解释目标内的具体对象，再局部标注。
- 隔着其他页面或直连会遮挡重要信息时，可从来源页面下沿出发，经下方空白通道接到目标页面下沿，优先两次圆角转弯。此时就近说明适用于同类对象的触发规则和动作结果；不必先从来源页侧面绕到底部，再沿目标页侧面爬回标题高度。
- 评估整组连线的清晰度，不孤立优化某一根线或只追求折角少。若从控件出线会穿过其他操作区，沿侧边又会与其他线相交，优先采用页面底边起线加通用动作说明。多条线按来源、目标和可用空白规划，减少折点、交叉与重叠。允许穿过来源页上无关键信息的空白；避免穿过中间页面、文字或控件。不要将“不得遮挡重要内容”扩张为“线不得叠在任何页面上”。页面位置保持用户已确认排法。
- 交付前放大检查每条线的颜色、4 px 线宽、起点圆点、终点三角箭头、60 px 折角，以及实际连接的动作与目标；缩回整板检查是否出现难以追踪的交叉或侧边绕行。

## 每根连线的语义与位置验收

不能只验颜色、线宽、箭头或线是否存在。逐根读取最终画板上的实际连线，并建立简短记录：来源页面、具体触发控件/区域、动作、目标页面或目标状态、线节点与标注节点。记录留在工作文件，不放进业务画板。

每根线必须逐项通过：

1. **起点正确**：相邻直连时从实际点击控件或区域旁起指，可叠在来源页上；跨页底部走线可从来源页面下沿起指，并有就近的具体动作说明。不能无依据从页面中段、无关标题或另一张状态卡上起指。
2. **终点正确**：箭头到对应目标页面或状态的可见边缘即可，底部绕行可接下沿；无需强制指向标题或内部字段。不能只进入包含多个对象的大组就算正确，更不能指向页外空白或无关模块。
3. **动作可读**：入口自带的按钮文案与连线关系清晰时可沿用；若线从页面边缘出发、入口无文字、跨距较长或存在多个可能入口，必须在线旁说明适用的控件/区域类型及动作结果，说明应表达可应用于未展示实例的行为规则。只写“点击”“跳转”不足以消除歧义。标注贴近对应线，不压线、不盖内容。
4. **关系正确**：确认这是真实操作/跳转，不把并列业务状态画成连续流程；每条线表达可辨认的来源类型、触发行为和目标，不与别的线或标注混淆。同类对象规则相同时只画代表路径；有依据的行为差异才另画分支，不因样例数据不同而逐项枚举。
5. **重排后仍成立**：移动页面、调整 Auto Layout、改变容器尺寸或重新分组后，用最终来源/目标的实际坐标重新定位所有受影响连线及标注。不要沿用重排前的绝对坐标；验证线的父级坐标系和目标所在坐标系一致。
6. **实际画布通过**：放大逐根查看起点、沿线标注、终点，再缩回整板检查遮挡与歧义。节点名称正确、坐标计算成功或局部导出正常均不能代替这一步；编辑器与导出不同，以用户实际画布继续排查。

任何一根线指错对象、无法判断点击哪里、漏掉必要代表路径，均为未通过。修复后重新检查受影响的完整路径，不通过就不能报告连线验收完成。

## 整板验收门槛

- 必须看 fit-to-board 的完整截图，不能只验手机页面和局部文字。
- 从整体上检查：方案是否真并列、子方向归属是否清楚、通用内容是否独立、是否存在无理由换行、是否出现右侧持续大面积留空而下方还在堆页面；状态组是否只是并列展示，跨页路径是否独立且只连接代表页面。
- 对只展示卡片的状态，放大核对卡片与原页面对应模块的锚点对齐；整板缩略图看起来相邻，不等于模块已对齐。
- 将下一组与当前行的剩余宽度比较：如果它能在保持正常间距和语义关系的条件下放入右侧，当前换行就应被质疑并重排。
- 可用行内占用宽度/可用宽度和整体长宽比作预警，不设脱离内容的硬比例。长宽比接近或超过 2 且多行仅使用左半边，是明显失败信号；不能靠缩窄画布、裁内容或缩图遮盖。
- 核验页面无溢出、无遮挡、无字体替换，完整页数量与交付范围一致。展示最终实际画板链接，未通过整板检查不得说已完成。

## 与入口规则的关系

内容保留、产品本体与交付外壳的边界、临时检查稿迁入、标题锚点以及有意裁切的判断，统一执行 [SKILL.md](../SKILL.md) 的对应章节。本文件只补充 Figma 的占地、结构与连线规则，不另设内容顺序或页面业务规则。
