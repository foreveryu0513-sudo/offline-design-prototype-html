# HTML 交付形式与离线验收

## 选择与保持格式

- 完整展示的默认入口为交互演示，顶层导航为交互演示、设计总览，最新与历史在总览内部切换；共用背景和难点，各版分别展示策略与方案；纯总览任务或本轮明确要求除外。总览继承指定历史 HTML 的阅读结构，不默认缩成一张超宽小字画布。

- 单文件：CSS、脚本、字体、图片、SVG/mask、背景图和交互引用页面均自包含，内联或 data URI；用户只拿这一个文件即可使用承诺的展示能力。
- 完整展示单文件：含设计总览与交互时，两者都嵌入文件；切换不能依赖旁边的 review.html、index.html 或本机路径。外壳适配手机高度，切换后不能重置不相关状态。
- 目录版：可用于开发维护；依赖 assets/ 时不能把其中的 index.html 称为可独立转发单文件。ZIP 是附加交付，不代替用户指定的单文件。
- 交付名称明确，不让同名“最终版”散落多个目录。沿用用户已经在用的路径更新，并说明手机附件旧副本不会自动更新。
- 演示控制、业务 UI、设计说明分区清楚，不在产品页加入实现说明或多余标签；总览只保留用户认可的内容与顺序。

## 打包根源

- 从一套源文件构建总览版、交互版和完整单文件；路由、共用 CSS、素材更新后同步所有已有交付版本。不要手改巨大 base64 HTML 而不回写源。
- 静态资源收集需覆盖 JS 模板、CSS url、背景、字体、SVG 和动态生成节点；不能只替换 HTML 的 img src。
- 不依赖远端字体/CDN、Figma 临时素材 URL、file:///Users/... 或源目录旁的资源。明确保留的外部“来源”链接可存在，但不应是展示或交互必需依赖。
- 内嵌图片按原比例，避免为打包体积降低到正文不可读。检查整个源文件而不是只检查落地页资源。

## 交付前的真实验证

1. 将准备交付的单文件复制到不含 assets 或其他源文件的临时目录，直接通过 file:// 打开；禁用网络/使用新浏览器上下文。验证不用本机已缓存素材也能显示。
2. 逐页打开交互目的页，检查图片 complete/naturalWidth、字体、图标、背景、控制台错误及失败请求；隐藏页和点击后才加载的素材也要测。
3. 设计总览：与原稿大画板对照，顶部背景/策略的字号与样式有来源；下方按当前项目确认的方案、页面/状态、通用模块和流程关系组织，不预设首页项目的固定顺序。文字可读、背景符合该媒介的已确认主题、说明紧邻对应页面、无意外空白或裁切、横向区域可达；保留当前稿中实际存在的示例与入口→目的页说明，并执行 delivery-visual-style.md 的样式对照。
4. 交互：运行逐页清单，检查导航/滚动/返回/弹层/固定操作；包含 iframe 的版本测外壳内实际尺寸，不能只测源 index.html。
5. 修改后重新构建；确认交付文件修改时间/哈希与刚测版本一致。截图和结果放工作证据目录，不自动进入设计总览。
6. 给出唯一明确的推荐发送文件和可点击路径；若同时交付两个版本，用“完整展示”与“交互离线版”等说明用途，不让用户猜。

不要承诺“任何人、任何软件都能打开”。可验证的表述是：资源已内嵌，已在指定浏览器离线打开；手机系统或聊天应用可能限制 HTML 附件脚本，未经真机验证需如实说明。发现目标环境不支持脚本时再按用户意愿补充替代交付，不擅自改变原要求。

## 浅色 HTML 素材边缘

Figma 深色与 HTML 浅色可以并存。检查单页素材未包含 Figma 外层深色画布，圆角外透明；在实际浅底放大检查圆角、阴影与抗锯齿边缘，无深色方角或晕边。深色已烘焙时重新导出源素材，不用覆盖或裁切掩盖。HTML 外壳字体来自已确认的浅色 HTML，产品 UI 字体仍保留原稿。
