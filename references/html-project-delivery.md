# HTML 项目交付契约

## 单一外壳，独立内容版本

交付实体按项目 → 版本 → 视图 → 节点组织。项目是长期入口，版本是不可变快照；视图分交互、总览，节点是方案分组、页面或交互状态。不要用日期文件夹或“最终版”代替版本关系。

统一 HTML 版式取自已确认的 11.3 浅色分区浏览模板，标准样式为 `../assets/overview-shell.css`：可读字号、纵向背景/策略、组内横排页图、同排顶对齐、分区浏览。最新和历史使用同一套角色、导航和主题；产品 UI 原貌不变。历史源文件以哈希留存，统一展示外壳属于派生视图，不冒充原始快照。历史没有交互时只提供总览与原文件，不虚构交互。

Figma 的既有版式、布局和排版参考不因 HTML 重组而改变。HTML 不强制复制 Figma 的坐标；二者内容、流程含义和版本来源必须对应。

顶层导航仅为交互演示（如有）和设计总览。设计总览依次展示共用的项目背景、设计难点，以及最新/历史版本切换；设计策略和方案内容归属于各自版本，不重复共用背景。继承历史 HTML 的信息结构和统一样式，历史选择后保持版本上下文。历史 iframe 不嵌套项目导航或重复前置说明。

分享操作跟随对象：项目链接属于个人站项目页，复制方案链接属于版本标题/切换区，复制页面链接属于页面预览或演示选页区。不要在全局导航放语义模糊的“复制当前链接”。Figma 来源与下载为辅助操作。

选择 Before / After 时，对比属于对应版本的方案内容，放在策略后的首个页面分区；历史版本切换独立保留，不能把旧版浏览入口当作对比交付。

## 地址与个人站

- 项目固定地址指向最新已发布版本；更新时地址不变。
- 版本地址包含不可变版本 ID 与文件摘要。发布后的内容变化创建新版本，不覆盖旧地址。
- 视图/节点使用 URL 状态（如 `#view=overview&version=...&node=...`）；刷新、粘贴打开和返回可恢复准确目标，不能只更新界面却不更新地址。
- 未知版本或节点提供明确未找到与项目返回入口，不悄悄显示最新稿。
- 个人站从同一交付清单读取项目、最新版本、历史、Figma 来源、快照与节点。周报引用项目/版本 ID，不复制另一份“最新”文件来源；同步后不能被旧配置覆盖回去。
- 站内项目页保留返回项目目录/周报的来源；交付原型的业务返回只在手机视口内，不能代替个人站导航。
- 嵌入浏览时复制按钮应复制实际项目、版本或节点的可访问地址。`file://`、localhost 只能标为本地预览，离线交付转发文件；不能把它们称为同事可访问的链接。
- 内网基址、发布目录和访问权限来自项目已授权环境。用户选择内网不等于允许公开上传；不得自行创建外网公开站。

## 交付清单

至少包含 `schemaVersion`、`projectId`、`title`、`currentVersion`、`figma`、`versions`、`nodes`。版本记录包含唯一 `id`、`label`、源文件、能力 `capabilities` 和真实快照日期；构建后增加 `url`、`sha256`。节点包含稳定 `id`、标签、所属版本/视图与 Figma 对应节点。

区分设计日期、快照日期和发布时刻。没有真实历史快照则明确没有，不拿当前文件伪造旧版。旧路由有引用时保留兼容入口。

## 一次交付执行

一次调用此 skill 负责串起以下阶段，不声称所有项目都能脱离设计工具自动生成：

1. 按当前 Figma 来源读取并导出完整内容，构建 HTML；没有 Figma 则按授权创建/整理，已有 Figma 不重复生成。Figma 写入仍走既有技能与验收。
2. 根据版本清单运行 `scripts/package_delivery.py manifest.json --out publish/project-id`，生成不可变版本文件、项目固定入口和 delivery.json。源文件必须已自包含。
3. 校验内容、路由、交互、离线资源、共享样式及历史哈希。失败不得推进最新已发布指针。
4. 使用目标个人站的现有数据适配器登记项目/版本。自动登记不等于自动编写周报结论；只把已确认的交付与验证状态关联为汇报证据。
5. 在已授权发布环境部署：先上传不可变文件，验证资源和哈希，再原子切换项目入口，最后更新站点索引。保留可回滚的上一入口。
6. 返回项目链接、版本/节点链接、Figma、单文件 HTML；区分 built、tested、published、verified。网络或凭据受阻时保留待发布包，说明阻点，不将规划地址说成已更新。

打包脚本只负责文件与清单，不负责登录、Figma 授权或远程发布。交付工具可统一，产品页面构建器仍继承各项目源文件，不能为“一键”重画产品 UI。

## 验收重点

首次进入、无交互版本、旧版预览、刷新深链、失效链接、iframe 返回、复制项目/版本/节点链接、窄屏控件、历史哈希、重复执行不增生版本、发布失败保留旧入口。必须验证真实结果，不仅匹配字段名。
