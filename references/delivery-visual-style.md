# Figma 大画板与 HTML 总览的样式契约

这份契约定义应继承哪些视觉属性，以及两个媒介如何保持内容与层级对应；不要求交付背景、文字颜色和字体完全相同。不是只写“参考原稿”，也不把某一个项目的深色主题强制推广到所有项目。

## 样式来源顺序

1. 用户本轮指定的交付模板或已修改画板。
2. 同项目已确认的交付大画板 / HTML 外壳。
3. 用户明确指定的跨项目模板。
4. 前三者没有可用来源时，按现有项目设计规范组合，并明确哪些交付外壳样式是新拟定的；不要声称已继承模板。

产品 UI 模板与交付外壳模板要分别识别；产品页的橙色品牌不代表交付画布也应为橙色。用户给出的模板结构应复用；交付内容数量变化可调整外壳的宽高和分区，不复制无意义空白。

## 内容归属与就近排版

前置说明（项目背景、设计难点、目标、策略）必须按 [SKILL.md 的强制要求](../SKILL.md#前置文案必须纵向排列强制) 单列纵向排列。这里的就近排版与后续横向页面布局均不得将前置说明改成多列。

先确定每个标题、正文、图示和注释属于哪个内容组，再安排距离。视觉上应先读出归属，再读出顺序；不能用一串等间距文本代替内容分组。

- 标题与其正文、页图与其标签等直接关联元素放在同一语义容器中。Figma 使用嵌套 Auto Layout，HTML 使用对应 section / flex / grid；父容器管理组间距，子容器管理组内距。禁止把不同组的标题、正文平铺在同一个等 gap 列表中。
- 从当前模板选定间距基准及组内、组间、分区三个语义 token，同类关系统一使用。满足组内距 < 组间距，分区距不小于组间距；优先使用基准的倍数。没有已确认数值时，组间距可先取组内距的 2–3 倍，再按字体行高和实际可见边缘校正。这是起始方法，不是跨项目固定像素或强制比例。
- 标题必须明显更靠近它引领的内容，而不是上一组正文。分别检查“上一组末行可见字形到标题”和“标题到所属正文首行可见字形”的距离；前者应明显更大。仅文本框 gap、8 的倍数或数学比例正确，不代表就近关系成立。
- 同级组使用相同对齐与间距规则；文字换行后容器自然增高，下一组随之移动。不要靠空行、空白占位、单个节点手动坐标、缩字或添加装饰分隔线来补救错误分组。HTML 清除组内默认 heading/p margin，避免 margin 叠加或折叠改变关系。
- 交付前主动检查全部同类组，而非只修被指出的一处。至少检查标题正文组、页面标签与页图、注释与所属对象；在完整画板及可读字号下确认归属。用一组较长正文或窄容器验证换行后关系仍成立，再恢复正式内容。失败就修容器或间距 token，并重定位受影响连线。
- 此规则针对交付排版；产品 UI 仍遵守其已确认组件规范。Figma 与 HTML 可以主题不同，但内容分组和远近层级必须一致。

## 项目标题栏与整板比例

标题栏是整张交付板的身份区，其高度、图标、标题字号、署名字号和留白须与当前画板规模协调。继承模板的结构和视觉层级，不照搬宽大模板的绝对尺寸。源稿中的 480px 栏高、100/120px 标题等是来源值，不是所有画板的固定规范。

- 先确定最终画板宽高、内容列数、页图尺度和正文分区，再决定标题栏的尺寸。对比栏高占整板高度的比例、标题相对画板宽度及下方章节的大小；少量页面的窄画板应相应收紧。宽度增加不意味着标题可以无限放大，也不能仅因长页增加了画板高度就放大标题。
- 把图标、标题、署名/日期、内边距与栏高作为同一套尺度调整，保留主次关系与对齐。不只缩一段标题，却留下过高的空栏或过大的图标。
- 作者、FD+ 等已确认身份信息必须完整可见；不能靠删除、裁切或挤出画板来让标题放下。先协调各组尺度和间距，必要时在标题栏内部合理分行；不改写署名或补造日期。
- 这些调整仅作用于交付标题栏，不缩放产品页面，也不连带改变产品字体。栏高变化后，由 Auto Layout 推动后续内容，重新按实际入口与目标定位流程线。
- 以整板视图验收：标题栏清楚但不抢占主体，不像独立封面；再放大检查标题与署名的可读性、完整性及间距。不要把一次项目采用的比例或像素值固化为跨项目常量。HTML 总览按其主题落实同样的比例关系。

## 开发重点说明：强调提示块

用于开发容易漏读、且影响实现的关键规则，例如复用边界、统一交互约定、例外状态和跳转结果。普通说明仍用原注释样式，不把所有文字都改成提示块。提示块属于交付外壳，放在对应页面外或流程标题下，不混入面向用户的产品 UI。

用户于 2026-11-05 确认的默认样式（750px 页图设计基准）：

| 属性 | 取值 |
|---|---|
| 背景 | 浅橙 `#FFEFE8` |
| 文字 | 深橙 `#CC490C`，保证浅底上的可读性 |
| 字号 / 行高 | `32 / 44px`，明显高于普通 `25 / 33px` 注释；同类提示统一 |
| 字体 / 字重 | 继承交付正文；本次确认样例为 Noto Sans SC Regular |
| 四边内边距 | `32px` |
| 圆角 | `24px` |
| 布局 | 垂直 Auto Layout / 对应 CSS；固定可用宽度、正文自动换行、容器随内容增高 |

- 单页规则与对应页图同宽；通用规则与所属流程组对齐，宽度不越过该组。宽度按真实内容和模板确定，不硬编码本次流程组的宽度。
- 标题、提示块、下一层小标题之间保留独立留白。此基准下，标题到提示块、页图到下方提示块优先留 `64px`；提示块增高时同步调整邻近排版，不能挤压小标题或覆盖页面、连线。
- 保持一句话或短段落表达完整规则；不要为了显眼再叠加大标题、图标、阴影或重复文案。同一规则有一个主要说明位置，其余位置按需简短引用。
- 以上数值是已确认的交付提示样式，不是产品组件规范。其他画布尺度和 HTML 总览按整体比例映射；用户本轮指定的模板优先，不单独缩小提示文字迁就空间。
- 验收同时查看局部与整板：文字不裁切、对比清楚、提示归属明确、同类样式一致；放大提示后，上下层级仍有足够留白，且未移动或改写无关产品内容。

## Figma 交付形态

- 真实可编辑标题栏与分区结构；主体用紧凑横向布局，按内容决定宽高。
- 大方案同级并列，使用业务章节文字标题；原因是说明文字，方案内方向按实际需要采用子标题或页面标签。通用状态和交互独立，不能因最后放置而成为末方案子级。白底标签仅用于更高的跨项目/场景分区，不由“方案”一词触发。
- 对齐页面顶部或对应关键模块，保留自然页高。不以拉伸页面、缩小字体、裁掉正文填补或消除空白。
- 页图原内容与其外部交付标签分离，便于整组移动。草稿不建组件的用户要求优先。

## HTML 交付形态

- **设计总览**：先继承用户指定 HTML 的阅读结构。分区浏览模板保留章节、可读字号和组内横向页图；画布模板才使用整体平移/缩放。与 Figma 保持内容、语义层级和流程关系对应，不强制照搬物理坐标；不能把所有模板都转换成超宽缩略画布。
- **浏览工具外壳**：目录、缩放、返回总览、版本/交互切换按已有 HTML 模板继承，视觉上让位于画布；只放本次需要的工具。没有来源时采用简洁克制的外壳并单独说明，不套通用营销站导航。
- **交互原型**：按产品 UI 原稿呈现手机视口、导航、内容和弹层，保留业务页面自身主题。工具按钮留在手机视口外，不混入产品页面。
- **字体与缩放**：单文件需内嵌可用字体或使用经确认的替代；字体缺失不能默默替换。缩放必须同时作用于字号、间距、页图、连线；支持放大阅读，不单独改小标题。
- **版本一致**：当前与历史沿用同一外壳样式，业务页面仍保留各版本原貌。不要为历史另设计一种报告主题。

验收时检查：白底标签是否有真实跨项目/高层场景依据；普通方案有无错误升层；说明是否低于标题；是否存在为了排满层级而新增的标题。源稿若有局部不一致，先按语义和本轮明确要求校正，不复制其所有偶然样式。

## 双主题交付与透明圆角（仅适用对应交付形式）

- 默认偏好：Figma 交付板可保留深蓝底以增强页图识别；HTML 采用用户认可的浅色总览及其字体。两种主题分别继承，不要求同色同字体；本轮明确模板优先。
- HTML 的具体浅色值、字体家族、字号层级与间距必须从已认可的首页前期方案 HTML 源文件/CSS 读取。指定文件与字号表见“HTML 总览共用字号表”；继承其交付样式，不复制首页业务内容。
- 交付文字和分区背景优先使用 HTML 原生文字/CSS，不整板截取深色 Figma 背景。产品页面内部的字体、颜色、素材、圆角和背景保持产品原稿，不跟随交付主题替换。
- 页图单独从对应产品节点导出，不带临时检查底板或交付画布。模块内部合法的底色必须保留。圆角外、异形轮廓外应为透明 alpha；需要透明时使用支持透明的 PNG/SVG，不用 JPEG。页面内部合法的深色区域不应被误删。
- 已烘焙深色角、边缘或底色的图片必须重新从源节点透明导出；不能靠网页换底色、盖白块、裁掉关键内容或统一额外圆角遮掩。
- 在实际浅色 HTML 背景上检查所有代表性素材，尤其圆角、阴影、抗锯齿边缘：无深色方角、深色晕边、透明区域被填黑、切角残留。仅检查文件有 alpha 通道不代表边缘合格。
- HTML 字体替换是交付外壳的明确主题映射，不是缺字体时静默 fallback。检查中文/英文、换行、层级与布局；在各主题内统一缩放文字、页图、间距和连线。

## 交付控件的内容安全区

- 标签、控件与反馈分别成组。标签到控件使用统一间距（常规 12px）；反馈与控件之间至少留 16px，换行后仍保持归属。
- 输入框、下拉框和按钮必须为文字及附属图标分别预留空间。交付外壳的常规控件左右文字内边距至少 16px；带尾部箭头的下拉框为箭头预留独立区域（例如右侧 44px、箭头距边 16px），不能依赖浏览器默认箭头内边距。
- 控件高度由行高与上下内边距共同决定（常规行高 24px、上下各 10px）；不通过固定高度挤压文字。产品内控件仍继承其指定组件，不套用交付外壳数值。
- 在最窄交付视口、最长选项和换行状态验收文字、箭头、边框、相邻提示之间的实际距离；使用 flex 换行和容器内边距解决空间不足，不以缩字、裁切或隐藏反馈解决贴边。

- 下拉框必须检查默认值、最长值和切换后的可见文字，不只检查箭头或 DOM。标签和箭头独立布局、内容区可伸缩；窄屏必要时换行。自定义选择器需提供语义、键盘操作、关闭和焦点状态。
